## 1. 概述

### 1.1 设计目标

pi-studybuddy 的 UI 是学生每天打开的桌面学习工作台。它必须做到三件事：

1. **打开即进入对话**：学生打开应用默认进入"💬 对话"，可直接问答；需要结构化学习动作时再进入 S1 每日首页及 S2-S7 工作台，不需要在菜单里找对话入口
2. **朗读随时可击发**：任何有文字内容的位置都有朗读按钮（TTS 跨子系统，02-PRD §3.9）
3. **隐私边界可视**：家长报告界面只展示脱敏聚合，学生侧也看不到完整 UUID（02-PRD §5.2）

### 1.2 设计原则（铁律）

1. **骨架稳定、业务可演化**：pi-desktop 五件骨架组件直接搬运改名（AppShell / SessionSidebar / FileExplorer / MarkdownBody 等），业务 UI 在其上自建（03-Architecture §6.1）
2. **学习场景优先**：会话语义从 coding agent 对话改为学习对话——附加学科标签/学习目标/错题关联（03-Architecture §6.7）
3. **规则优先 UI 不撒谎**：每日首页/速背卡/冲刺计划由规则聚合，UI 不展示 AI 幻觉为事实
4. **防泄露先于交互**：作答前 DTO 不含正确答案；家长报告界面不含原文/题干/答案/作答/错因/完整 UUID
5. **TTS 无处不在**：每个 Markdown/纯文本内容区都内嵌朗读入口，全局朗读控制条常驻
6. **单机桌面交互**：不模拟 Web 多标签页浏览器行为；文件经 `@` 引用进入对话
7. **中文优先**：所有界面文案中文；错误消息中文可操作（06-API §2.3）

### 1.3 技术栈

**借鉴 pi-desktop**（03-Architecture §6.2）：

| 技术 | 用途 | 来源 |
|---|---|---|
| React 19 + Vite | renderer 框架 | pi-desktop 直接复用 |
| react-markdown + remark-gfm + remark-math + rehype-katex | Markdown 渲染 + 公式 | pi-desktop 直接复用 |
| rehype-raw + rehype-sanitize | HTML 安全渲染 | pi-desktop 直接复用 |
| SyntaxHighlighter | 代码高亮 | pi-desktop 直接复用 |

| zustand（或 Context） | 状态管理 | pi-studybuddy 自选（学习状态较复杂） |

## 4. 标签页结构（对话 + 学习工作台）

### 4.1 标签页总览

主内容区顶部 TabBar（借鉴 pi-desktop `TabBar.tsx`）：

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 💬 对话（默认）│ 📊 首页 │ 📁 资料 │ 📝 笔记 │ ✏️ 练习 │ ❌ 错题 │ 🎯 冲刺 │ 📋 报告 │ 🎤 采集 │
└─────────────────────────────────────────────────────────────────────────┘
```

| Tab | 角色 | 触发条件 | 主要 RPC |
|---|---|---|---|
| **💬 对话** | **pi 原生 AI 对话**（默认打开，零碎问答的常驻入口） | 应用启动即默认 | `agent.events` 流式 + pi 原生工具 |
| 📊 首页 | S1 每日简报 | 切换到该 Tab | `studybuddy_daily_brief` |
| 📁 资料 | S2 资料上传与管理 | 选课程后 | `materials.*` |
| 📝 笔记 | S2 笔记预览/导图 | 选资料后 | `notes.*` / `notes.getMindMap` |
| ✏️ 练习 | S3 限时练习 | 选模块后 | `practice.*` |
| ❌ 错题 | S4 错题改错 | S3 批改后有错题 | `mistakes.*` / `weakPoints.*` |
| 🎯 冲刺 | S5 期末冲刺 | confirmed 考试+距考≤N天 | `mockExams.*` / `cramCards.*` / `cramPlan.*` |
| 📋 报告 | S6 家长报告（学生侧） | 学生触发/调度自动 | `reports.*` / `deliveries.*` |
| 🎤 采集 | S7 课堂采集 | 学生选课程后 | `classCapture.*` |
| 💾 备份 | 备份恢复面板（T-M4-019 增补，04-Todo §6.6"BackupPanel 可达"） | 切换到该 Tab | `backup.*` + `backup.progress` |

**设计意图**（响应用户反馈）：
- pi 本身就是 AI coding agent，**天生自带对话能力**——这是 pi-studybuddy 作为"专属 studybuddy"的根基，不能废弃
- 学生在"💬 对话"里随时与 AI 自由问答（"帮我理解极限的 ε-δ 定义"/"这道题怎么做"/"导数和积分的关系"），不必每次走结构化的 S1-S7 标签页
- S1-S7 标签页是"结构化学习工具"区（规则驱动 + 工具化），对话 Tab 是"自由探索"区（AI 原生）
- 两层并存：学生既能在结构化工具里完成闭环（上传→练习→错题→冲刺），又能在对话里零碎提问——避免被迫使用别的 AI

### 4.2 对话 Tab：通用 AI 问答（pi 原生，默认）

**依据**：pi 底座原生能力 + 03-Architecture §6.7（会话管理业务化）+ 02-PRD §1.2（AI 受约束辅助）

```
┌─────────────────────────────────────────────────────────────────┐
│  💬 学习对话  |  📐 高数  |  目标：极限练习  |  关联错题：#极限-001│
├─────────────────────────────────────────────────────────────────┤
│  🤖 你好，今天想学点什么？（上下文已注入：L1 画像 + 当前学期/课程） │
│                                                                   │
│  学生：帮我理解极限的 $\epsilon-\delta$ 定义                       │
│                                                                   │
│  🤖 极限的 $\epsilon-\delta$ 定义是...                             │
│  [工具调用：studybuddy_tts_speak]  🔊 已朗读                       │
│                                                                   │
│  学生：@第2章笔记.pdf 第3页那个例子                                │
│                                                                   │
│  🤖 根据笔记第3页...                                               │
│  [工具调用：studybuddy_generate_note] ✅ 已生成笔记 [查看]         │
│                                                                   │
│  学生：给我出 5 道导数定义的练习题                                 │
│  [工具调用：studybuddy_generate_questions] ✅ 已生成 5 题 [去练习] │
│                                                                   │
├─────────────────────────────────────────────────────────────────┤
│  [📎 @文件]  [📐 学科]  [输入消息...]                    [发送]   │
└─────────────────────────────────────────────────────────────────┘
```

**pi 原生能力承载**（不废弃，全保留）：

| 能力 | 来源 | pi-studybuddy 落地 |
|---|---|---|
| **流式回复** | pi `Streams["agent.events"]` | ChatWindow 直接复用 pi-desktop |
| **工具调用视图** | pi `countToolCallBlocks` | 直接复用 + 学习工具图标（studybuddy_*） |
| **上下文压缩** | pi `onContextUsageChange` | 直接复用，长对话自动压缩 |
| **@文件引用** | pi-desktop `allowed-roots.ts` + `session-file-references.ts` | 限当前课程资料 |
| **多模型切换** | pi `modelsConfig.get/set`（业务数据根 `<dataRoot>/config/models.json`） | 设置页配置（§9.2） |
| **registerTool 工具** | pi 原生工具调用 | S1-S7 + TTS + 备份恢复全部工具可在对话中由 AI 自主调用 |

**学习场景业务化**（在 pi 原生之上叠加）：

| 业务化项 | 说明 |
|---|---|
| **学科标签** | 输入区可标注学科（颜色标识），影响 AI 上下文 |
| **学习目标** | 会话可设目标（"极限练习"），影响工具调用偏好 |
| **错题关联** | 会话可关联错题 ID（从 S4 跳转，AI 可读取错题上下文） |
| **L1 画像注入** | `before_agent_start` 钩子注入学习者画像（03-Architecture §2.3） |
| **L3 会话检索** | `turn_end` 钩子增量索引，历史会话可检索 |
| **TTS 随时可击发** | 任意 AI 回复可朗读（§5） |
| **工具调用可跳转** | AI 调用 `studybuddy_generate_note` 后，"查看"按钮跳转到笔记 Tab |

**关键约束**：
- **对话是基础功能，不是可选**——pi-studybuddy 作为"专属 studybuddy"，必须让学生在本机完成所有 AI 问答，不被迫使用别的 AI
- **AI 受约束辅助**（02-PRD §1.2）：AI 只负责受约束生成/抽取/批改/润色，不接管决策、不替学生改写事实
- **工具调用透明**：每次 AI 调用工具都可视化展示，学生知道 AI 做了什么
- **Simple Mode**（03-Architecture §2.5）：学生可在设置中切换简化模式，降低上下文消耗

**与 S1-S7 标签页的关系**：
- 对话 Tab 是"自由探索"——学生零碎提问，AI 自由回答 + 按需调用工具
- S1-S7 标签页是"结构化工具"——学生走闭环（上传→练习→错题→冲刺），规则驱动
- 两者数据贯通：对话中 AI 生成的笔记 → 笔记 Tab 可见；练习 Tab 的错题 → 对话中可 @引用讨论
- 会话列表（左侧栏 §3.3）统一管理所有对话，支持学科+目标+内容模糊搜索

## 5. TTS 朗读 UI（跨子系统随时可击发）

### 5.1 全局朗读控制条

**依据**：02-PRD §3.9 + 07-Workflow §4

朗读控制条**常驻**在主内容区顶部（见 §2.1 布局图）：

```
┌─────────────────────────────────────────────────────────────────┐
│  🔊 TTS  |  引擎：SAPI（离线）▼  |  语速：1.0x ━●━━━  |  停止    │
└─────────────────────────────────────────────────────────────────┘
```

**控制项**：
- **引擎切换**：SAPI（默认离线）/ edge-tts（音质好需网络）
- **语速调节**：0.5x ~ 2.0x
- **播放控制**：播放 / 暂停 / 停止
- **状态显示**：当前朗读内容标题 + 进度

**API**：`tts.speak` / `tts.control` / `tts.switchEngine` / `tts.getStatus`（06-API）

### 5.2 内嵌朗读按钮

**每个有文字内容的区域都有独立的朗读入口**：

| 位置 | 朗读内容 | 触发 |
|---|---|---|
| 首页每日简报 | 简报全文 | "朗读今日简报"按钮 |
| S2 笔记预览 | Markdown 笔记正文 | 笔记标题栏"朗读"按钮 |
| S2 知识模块 | 模块内容 | 模块卡片"朗读"按钮 |
| S3 练习结果 | 错题解析 | "朗读错题解析"按钮 |
| S4 错题详情 | 错题解析/复盘笔记 | "朗读"按钮 |
| S5 速背卡 | 速背卡内容 | "朗读此卡"按钮（考前每日） |
| S5 冲刺计划 | 计划内容 | "朗读计划"按钮 |
| S7 转写文本 | 转写结果 | "朗读转写文本"按钮 |
| 任意 Markdown | Markdown 内容 | 内容区"朗读"按钮 |

### 5.3 朗读状态反馈

```
朗读中 → 控制条高亮，进度条显示当前位置
        → 当前朗读段落高亮（类似阅读器朗读模式）
暂停   → 控制条暂停状态，可继续
完成   → 控制条归位，可选"标记已复习"
```

### 5.4 标记已复习

**依据**：07-Workflow §4.3

朗读完成后（或学生主动），可标记"已复习"：
- 点击"标记已复习" → 写 `study_events`（`event_type=practice_reviewed`）
- 朗读本身不持久化，仅"已复习"标记写 StudyEvent
- **API**：`events.markReviewed({refType, refId})`

### 5.5 引擎降级

```
edge-tts 朗读失败 → 自动降级 SAPI → 控制条提示"已切换到 SAPI"
SAPI 不可用（非 Windows）→ 提示"系统 TTS 不可用，请安装 edge-tts"
```

### 7.1 学习会话语义

pi-desktop 的会话是 coding agent 对话，pi-studybuddy 业务化为**学习对话**：

| 学习目标 | 无 | 目标标题（如"极限练习"） |

| 流式回复 | `Streams["agent.events"]` | 直接复用 |
| 工具调用视图 | `countToolCallBlocks` | 直接复用 + 学习工具图标 |
| 上下文压缩 | `onContextUsageChange` | 直接复用 |

### 7.2 会话交互

## 11. 安全与隐私 UI 边界

### 11.1 不展示的内容（铁律）

**依据**：02-PRD §5.2 + 08-Test §7.2

UI 层**绝不展示**：
- 完整 UUID（只显示短 ID 或 `极限-001` 人类可读 ID）
- API Key（只显示"已配置/未配置"）
- 真实渠道地址（邮箱/Webhook URL，只显示别名"妈妈邮箱"）
- 内部错误栈（只显示中文可操作消息）
- 文件绝对路径（只显示相对路径或文件名）
- SQL 语句
- 学生隐私正文（家长报告中）

### 11.2 安全交互

- **敏感操作二次确认**：归档学期 / 恢复覆盖 / 删除课程 → 弹窗确认
- **许可确认强制**：S7 课堂采集必须勾选合规确认
- **密钥输入**：API key 输入框 `type="password"`，提交后走 credential-vault，不回显
- **错误消息**：统一 6 错误码中文消息，不暴露内部

### 11.3 桌面通知与消息中心

**依据**：03-Architecture §7.4（推送目标改为桌面通知 + 应用内消息中心）

```
┌──────────────────────────────────┐
```

## 13. 响应式与可访问性

### 13.1 响应式（借鉴 pi-desktop `useIsMobile.ts`）

- **桌面（>1024px）**：三栏布局（左导航 + 主内容 + 右面板）
- **平板（768-1024px）**：两栏（左导航折叠为图标 + 主内容），右面板改为抽屉
- **窄屏（<768px）**：单栏 + 抽屉式导航（虽然 v0.1 只 Windows 桌面，但保留响应式基础）

### 13.2 主题（借鉴 pi-desktop `useTheme.ts`）

- **浅色/深色主题**：跟随系统或手动切换
- **学习场景配色**：学科标签颜色（数学=蓝/英语=红/物理=绿/化学=紫/...）
- **状态颜色**：success=绿 / warning=黄 / error=红 / info=蓝
