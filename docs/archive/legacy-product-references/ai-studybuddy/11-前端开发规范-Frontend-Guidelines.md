# AI StudyBuddy 前端开发规范

**版本**：v1.5
**日期**：2026-07-28
**状态**：有效；覆盖 Phase 0.8 前端基线、Phase 1 学生端与配置中心、Phase 2 S5 页面及工作台集成
**触发原因**：开始编写第一个正式前端页面前，统一最小前端的技术栈、页面边界、接口调用和渲染安全规则。

---

## 1. 目标与适用范围

本规范适用于 `I:\ai-studybuddy\packages\frontend` 中的正式前端实现。当前代码已覆盖 S1–S4 学习闭环和共同底座设置页；以下最初流程仍是 Phase 0.8 的基础路径：

```text
创建课程 / 考试目标 → 上传资料 → 等待处理 → 查看笔记与思维导图 → 查看知识模块和关联学习任务
```

当前只追求功能可用、错误可理解、数据不丢失；不追求复杂视觉设计、多人账号、移动端适配或通用设计系统。

前端只消费后端 API，不直接读取 SQLite、上传目录、临时文件或 AI Provider 配置。资料原文、真实 API Key 和本机绝对存储路径不得进入浏览器包。

Phase 1-T08 配置中心已按独立计划实现。前端只负责输入配置、触发测试和展示脱敏状态：秘密使用密码输入框，提交后清空本地表单，不写入 `localStorage`、URL、埋点或错误日志；已保存的秘密不回显。AI、SMTP、飞书分别提供测试动作和结果反馈，不能用一个“配置完成”布尔值掩盖渠道状态。

## 2. 最小技术选型

| 能力           | 选择                                                             | 当前理由                                       | 本阶段不选                     |
| -------------- | ---------------------------------------------------------------- | ---------------------------------------------- | ------------------------------ |
| 应用框架       | React 18 + TypeScript                                            | 组件化适合三页交互；类型可复用共享对象         | Next.js、SSR、微前端           |
| 本地开发与构建 | Vite                                                             | 配置少、启动快，适合 Windows 单机浏览器页面    | 自建 webpack                   |
| 路由           | React Router                                                     | 三个正式页面需要稳定 URL、刷新后可回到对应页面 | 手写 Hash 跳转                 |
| 服务端数据状态 | 页面级 `useState` + 自定义 hooks                                 | 当前数据量和页面数量小，便于理解和调试         | Redux、Zustand、React Query    |
| HTTP           | 浏览器原生 `fetch` + 统一 `api-client.ts`                        | 无额外依赖，强制统一处理 API 信封与错误        | 页面中散落的 `fetch`、axios    |
| 样式           | 单个全局 CSS + 页面/组件 CSS                                     | 功能优先，避免过早引入 UI 组件库               | Tailwind、组件库、设计令牌体系 |
| Markdown       | `react-markdown` + `remark-gfm` + `remark-math` + `rehype-katex` | 满足笔记正文、表格与数学公式展示               | `rehype-raw`、直接插入 HTML    |
| 数学样式       | `katex`                                                          | 轻量、可本地渲染                               | MathJax                        |
| 思维导图       | `markmap-lib` + `markmap-view`                                   | 消费后端已生成的 Markdown 导图数据             | 自建 SVG 导图、在线导图服务    |
| 文件上传       | 原生 `<input type="file">` + 拖拽区域                            | 可访问、实现小、满足拖拽或选择文件             | 第三方上传组件                 |

依赖只在 T08 实际需要时加入 `packages/frontend/package.json`。新增库必须有明确用途，不能为了未来可能使用而预装。

## 3. 包与目录边界

前端包固定为 `I:\ai-studybuddy\packages\frontend`，包名为 `@ai-studybuddy/frontend`。它依赖 `@ai-studybuddy/shared` 获取跨端类型；不得从 `packages/backend/src` 导入代码或类型。

文档中的物理 Windows 绝对路径保留反斜杠；目录树、包内相对路径、URL、导入路径和命令参数统一使用 `/`，与 Vite、Node.js 和跨平台工具链保持一致。

建议目录：

```text
packages/frontend/
  index.html
  package.json
  tsconfig.json
  vite.config.ts
  src/
    main.tsx                 # React 入口、全局 CSS 与路由挂载
    app.tsx                  # 路由壳、全局导航、全局错误提示
    styles/global.css         # 最小全局布局、表单、反馈样式
    api/
      api-client.ts           # API 基地址、信封解析、统一错误
      study-rhythm-api.ts     # courses / exams / study-tasks / timeline
      note-builder-api.ts     # materials / notes / knowledge-modules
    components/
      app-navigation.tsx      # 三页导航
      feedback-message.tsx    # loading / empty / error 的统一可见反馈
      file-dropzone.tsx       # 选择文件与拖拽上传
      material-status.tsx     # 资料与 Job 状态、重试入口
      markdown-note.tsx       # Markdown + KaTeX 安全渲染
      mind-map.tsx            # Markmap 生命周期封装
      knowledge-module-list.tsx
    hooks/
      use-api-request.ts      # 可取消请求、loading / error 状态
      use-material-polling.ts # 仅在资料未终态时轮询
    pages/
      course-page.tsx         # 课程列表 + 创建课程/考试目标
      material-upload-page.tsx# 资料上传 + 处理状态
      note-page.tsx           # 笔记、导图、知识模块、关联学习任务
    types/
      view-models.ts          # 仅放前端展示组合类型；跨端类型放 shared
```

页面负责组合业务流程和页面状态；组件负责可复用展示或交互；`api/` 只负责 HTTP 请求与响应转换；`hooks/` 只负责可复用状态逻辑。禁止组件直接调用 `fetch`，禁止页面自行解析 `{ success, data, error }` 信封。

## 4. 页面、路由与 MVP 边界

| URL              | 页面           | Phase 0.8-T08 基线能力                                                          | 不做什么                                 |
| ---------------- | -------------- | ------------------------------------------------------------------------------- | ---------------------------------------- |
| `/courses`       | 课程与考试目标 | 读取课程/考试列表；创建课程；为指定课程创建考试目标；明确显示成功和失败         | 学期管理、编辑/删除、复杂日历            |
| `/materials`     | 资料上传       | 选择或拖拽文件；选择所属课程；上传；展示资料处理状态、失败原因与重试入口        | URL 导入、批量队列管理、在线预览原文件   |
| `/notes/:noteId` | 笔记与知识模块 | 读取笔记；Markdown + KaTeX 展示；展示 Markmap；按课程展示知识模块与关联学习任务 | 富文本编辑、手工编辑导图、S3/S4 练习流程 |

默认进入 `/courses`。页面间必须使用前端路由跳转，不能依赖浏览器后退来维持关键状态。缺少必填的 `semesterId`、课程或笔记 ID 时，页面显示可操作的中文空状态，而不是发出无效请求。

笔记页的固定进入路径为：用户在 `/materials` 上传资料 → 页面读取该资料的处理状态 → 后端返回可用 `noteId` 后，资料状态组件显示“查看笔记”链接 → 跳转到 `/notes/:noteId`。资料尚未生成笔记、需要人工补文或生成失败时，不生成无效笔记链接，保留对应的状态说明与重试/补文入口。

当前后端以 `semesterId` 作为请求边界。T08 在页面顶部提供一个明确的“当前学期 ID”输入或固定开发值，并将其集中保存在应用壳的状态中；不能将该值散落硬编码到各页面。正式的学期选择/初始化 UI 留给后续任务。

当前完整路由事实以 `docs/15` 为准：19 个学习业务路由加 `/settings` 设置页，共 20 个路由页。T09A 已用学期创建、选择、切换和后端 current 恢复替代手工输入 UUID；Phase 2 又增加模拟考 4 个路由、临考速背 1 个路由和冲刺计划 1 个路由。

## 5. API 调用与数据状态

### 5.1 API 基地址与环境变量

- 后端默认地址为 `http://127.0.0.1:3000/api`；实际端口以 `VITE_API_BASE_URL` 为准。
- 只允许通过 Vite 暴露的 `VITE_*` 变量读取前端配置。
- `VITE_API_BASE_URL` 只能是本机后端 API 地址，不包含密钥、数据库路径或文件系统路径。
- 在 `packages/frontend/.env.example` 记录变量名和示例值；真实 `.env.local` 不提交。

### 5.2 统一 API 信封

后端成功响应固定为：

```ts
{ success: true, data: T }
```

分页成功响应可额外带有：

```ts
{ success: true, data: T, meta: { page: number, pageSize: number, total: number } }
```

失败响应固定为：

```ts
{ success: false, error: { code: string, message: string } }
```

`api-client.ts` 必须：

1. 设置 JSON 请求头；上传 `FormData` 时不手动设置 `Content-Type`；
2. 检查 HTTP 状态和 JSON 信封；
3. 将后端 `error.message` 转为可展示的中文错误；
4. 对网络失败、非 JSON 响应和超时提供统一兜底错误；
5. 返回已解包的 `data`；分页请求同时以统一 `ApiPage<T>` 结果返回 `data` 与 `meta`，使页面和组件不接触信封细节；
6. 支持 `AbortSignal`，页面卸载后不再更新旧请求结果。

创建动作成功后，应重新读取受影响列表或使用服务端返回的数据更新本页状态；不假设本地生成的 ID、状态或排序与服务端一致。

### 5.3 错误、加载与空状态

每个请求型区域必须分别有：加载中、空数据、可理解的失败消息和重试动作。错误不得只写入浏览器控制台，也不得把内部异常堆栈直接展示给学生。

提交按钮在请求进行中禁用，防止重复创建课程、考试、任务或重复上传。成功提示要说明下一步，例如“资料已上传，正在后台处理”。

## 6. 上传与资料处理轮询

### 6.1 上传规则

- 使用 `POST /api/materials/upload`，以 `multipart/form-data` 发送 `file` 以及后端要求的归属字段（至少 `semesterId`、课程实例 ID）。
- 上传前在前端做基础检查：未选择课程、未选择文件、文件大小为 0 时直接提示；文件类型和大小的最终判定以服务端为准。
- 不在前端读取、解析或上传资料全文到额外第三方服务；文件只发给本机后端。
- 上传完成后立即显示服务端返回的资料记录，而非等待转换完成。

### 6.2 轮询规则

- 资料页面通过 `GET /api/materials` 或 `GET /api/materials/:id` 查询状态；只轮询当前页面中未进入终态的资料。
- 第一次查询在上传成功后或页面进入时立即执行；连续未终态时采用指数退避：`2 秒 → 4 秒 → 8 秒 → 16 秒 → 30 秒`，之后维持 30 秒上限。任一资料状态变化、用户手动刷新、重试后或页面重新可见时，重置为 2 秒。
- 页面隐藏、离开页面或资料全部终态时停止轮询；恢复可见时先立即查询，再按上述规则继续。
- 终态至少包含成功、需要人工补文、失败等后端返回的终态；状态枚举以 `@ai-studybuddy/shared` 类型和后端实际响应为准，不在前端另造业务状态。
- 转换或 AI 生成失败时，显示服务端返回的原因，并按已有 API 提供“重试转换”“重试生成笔记”或“手动补充文本”入口。
- 轮询不是长时间等待的遮罩：用户始终可离开页面，回来后重新读取状态。

## 7. 笔记、公式与思维导图渲染安全

### 7.1 Markdown 与 KaTeX

- 只用 `react-markdown` 渲染后端提供的 Markdown 字符串。
- 启用 `remark-gfm`、`remark-math` 与 `rehype-katex`，并在入口加载 KaTeX CSS。
- **禁止**使用 `rehype-raw`、`dangerouslySetInnerHTML` 或任何未经净化的 HTML 注入方式。
- 链接仅允许安全协议；外部链接以新标签页打开时使用 `rel="noreferrer noopener"`。
- 渲染出错时保留原始 Markdown 的只读降级展示，不能令整页白屏。

### 7.2 Markmap

- 思维导图输入来自后端生成的 Markdown/导图文本，不执行其中的 HTML 或脚本。
- `mind-map.tsx` 负责初始化、更新和销毁 Markmap 实例，页面卸载时必须清理 SVG 与监听器，避免重复挂载和内存泄漏。
- 导图生成缺失、内容为空或渲染失败时显示“暂无法展示思维导图”，笔记正文和知识模块仍可使用。
- 不把导图 SVG 字符串作为 HTML 直接注入页面。

## 8. 数据对象与跨系统边界

前端使用 `Course`、`Exam`、`Material`、`Note`、`KnowledgeModule`、`StudyTask`、`StudyEvent` 等共享对象。字段和状态以 `@ai-studybuddy/shared` 为唯一类型来源；前端新增的筛选、展开状态、上传进度等展示状态可放在 `src/types/view-models.ts`。

对象流仍遵守：

```text
Course → Exam / Material → KnowledgeModule → StudyTask → StudyEvent
```

T08 可展示知识模块关联的学习任务，但不得在前端臆造“资料已生成知识模块”“任务已完成”等业务结论。所有业务状态必须来自 API。

## 9. 可访问性与最小交互质量

- 表单控件必须有中文可见标签，错误信息应与对应输入关联。
- 文件拖拽区必须同时提供可键盘操作的“选择文件”按钮，不能只支持鼠标拖拽。
- 加载、上传和处理状态用文字表达，不能只依赖颜色或动画。
- 主要操作完成后保留清晰结果提示，页面焦点不应无故丢失。
- 页面使用语义化 HTML；不以复杂动画、图表或大面积装饰替代功能反馈。

## 10. 开发、测试与验收

### 10.1 开发约定

- 前端开发通过 workspace 命令启动，并与本机后端同时运行。
- workspace 已提供前端 `dev`、`build`、`type-check` 和 `test` 命令；后续修改不得破坏 backend/shared 命令。
- 格式治理仍按 `docs/04` 的独立候选任务分批推进，不在业务任务中制造全仓格式化 diff。
- API 路径、字段名、状态名和中文文案不得散落复制：路径集中在 API 模块，重复文案按需要集中到组件或常量。

### 10.2 最小自动化验证

Phase 0.8-T08 建包时至少补充前端可运行的类型检查、构建检查，以及关键页面/API 客户端的单元或组件测试。当前新增页面继续遵循同一原则：

1. API 客户端正确解包普通和带 `meta` 的成功信封、失败信封，并将网络失败转为统一错误；
2. 上传请求使用 `FormData`，不手动覆盖 multipart 边界；
3. 非终态资料才按退避规则触发轮询，离页/隐藏后停止、恢复时立即刷新；
4. Markdown 渲染配置不启用原始 HTML；
5. 页面在空数据、失败与成功后均提供可见中文反馈。

### 10.3 Phase 0.8-T08 基础页面人工验收

在本机启动前后端后，按下列顺序验证：

1. 创建课程，并为其创建考试目标；刷新页面后仍能读到；
2. 选定课程，选择或拖入一个受支持资料并上传；
3. 看到处理中状态，处理完成或失败后看到明确状态与可用后续操作；资料生成笔记后，点击“查看笔记”进入对应 `/notes/:noteId`；
4. 打开笔记页面，确认正文 Markdown、数学公式和思维导图分别可用或各自优雅降级；
5. 确认知识模块能显示其来源资料和关联学习任务；
6. 断开后端或输入错误地址，确认页面展示中文错误且不会白屏；
7. 执行 `pnpm type-check`、`pnpm -r --filter frontend run build`、`pnpm test`，以及仓库文档治理检查和 `git diff --check`。

Phase 1-T08 配置中心另需验收 `/settings` 的运行状态、AI/SMTP/飞书分区、密码输入、成功后秘密清空、失败固定错误码和 `/courses` 首次配置提示；自动化不得依赖真实外部服务。

### 10.4 Phase 2 S5 页面验收

- 模拟考页面必须覆盖生成入口、模拟卷详情、限时作答、刷新恢复、提交冲突安全态和结果/模块分析；正确答案只在提交后的结果契约中出现。
- 临考速背和冲刺计划页面均只保存必要标识或草稿状态，不把卡片正文、题干、答案、秘密或完整 UUID 写入浏览器持久存储。
- 考试工作台冲刺区只聚合既有入口与只读状态；未确认考试、窗口未开始/已结束、空建议、请求失败和跨考试切换均须有可见且不串数据的状态。
- Phase 2 前端自动化当前为 26 个测试文件、137/137 tests；完整 `e2e/` 为 15 个 spec、21/21 Playwright tests。后续变更不得通过删除、跳过或弱化断言维持通过。

## 11. 当前非目标

Phase 0.8-T08 当时不实现以下内容；其中配置中心、学期产品化、S3/S4 页面和 S5 Phase 2 页面现均已由后续获批任务完成。以下仍保留为当前非目标或需新门禁的能力：

- 登录、多用户、云同步、远程访问或家长 Web 面板；
- 完整学期设置、课程/考试编辑删除、日历视图或复杂排程；
- URL 资料导入、批量上传队列、在线原始文件预览；
- 富文本笔记编辑器、手工思维导图编辑、导出打印；
- S6 家长 Web 面板；家长继续只接收异步脱敏报告。Phase 3 当前仅恢复高权重必做项，且不包含家长登录或 Web 面板；
- 完整 S7 实时录音、视频、说话人分离和后台进度页面；当前仅实施资料页内受控 WAV 转写卡。
- 设计系统、深色模式、响应式专项优化或像素级视觉还原。

后续页面或能力进入实现前，先检查其所属子系统 PRD、架构边界及本规范是否仍适用；需要扩展时以小步增量修订本规范，避免提前设计大而全的前端框架。
