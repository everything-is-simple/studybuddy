## 1. 启动与健康检查（OPS-START-001）

1. 确认运行模式、版本、Node/Electron 运行时和当前数据根；默认根为 `%LOCALAPPDATA%\PiStudyBuddy`，测试必须改到 `H:\pi-studybuddy-tmp\runs\<task-id>\`。
2. 确认 Electron main/preload/renderer/agent-host 启动，IPC 只监听 `127.0.0.1`，无公网入口。
3. 确认 `global.db`、需要的学期 `sem.db` 可打开；建库辅助已关闭临时连接，不遗留 WAL/SHM 锁。
4. 执行 `system.ping`、代表性只读 RPC 和版本/数据根脱敏摘要；失败时保留结构化结果文件，不把栈或绝对路径写入 DOM。
5. 启动失败、数据根不可写或 SQLite 锁定时停止业务操作，转到 §6 诊断；不得用 fixture 冒充健康。

## 2. 数据根与 SQLite（OPS-DATA-001）

- 生产根：`%LOCALAPPDATA%\PiStudyBuddy`；测试根：`H:\pi-studybuddy-tmp\runs\<task-id>\`。
- 检查 global/semester/l3 数据库所有者、schema 版本、连接关闭和单写进程边界。
- 文件—数据库双写必须记录顺序、失败补偿、孤儿文件清理和恢复回读；未知落点标记 `待核验`。

## 3. 依赖健康（OPS-DEP-001）

记录每项依赖为 `可用`、`不可用但可恢复` 或 `未覆盖`：模型/凭证、WPS、OCR、whisper、TTS、文件对话框、Electron runtime。不可用时必须显示中文责任和恢复入口；不得静默回退 fixture，不得宣称核心闭环通过。

## 4. 备份、恢复、迁移、升级、卸载（OPS-BACKUP-001）

| 场景 | 现场检查 | 必须留下的证据 |
|---|---|---|
| 备份 | 范围、checksum、敏感内容、失败残件 | `release-evidence` 数据资产表 + 包哈希 |
| 恢复 | 新根/覆盖规则、schema 兼容、失败原子性 | 恢复前后清单 + 重启回读 |
| 迁移 | 版本标识、备份前置、回滚 | migration log + failure path |
| 升级 | 旧数据、DPAPI 凭证、可启动性 | 安装/升级/再次启动 JSON/截图 |
| 卸载 | 程序文件与业务数据分离，用户明确确认 | 卸载结果 + 数据保留/删除选择 |

当前未有完整真机恢复/升级/卸载证据时，状态保持 `未覆盖`，不因安装成功而升级。

## 5. 安全诊断（OPS-SEC-001）

- 诊断摘要只允许 allowlist 字段：版本、脱敏状态码、阶段、耗时桶、数量级和可恢复建议。
- **不记录**请求正文、模型完整输出、base URL、密钥、完整 UUID、绝对路径、学生资料原文或错误栈。
