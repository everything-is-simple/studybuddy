**版本**：v0.1.2

**状态**：✅ 已审查批准；T-M5-011 执行中
**权威性**：系统集成四份文件之一；本文件规定系统何时可以称为正常运行和可交付；阶段执行必须遵循 `04-系统集成固定工作流与阶段门禁.md`。

## 1. 唯一验收顺序

```text
当前开发机真实主路径
→ 开发机重启回读
→ 固化运行资源和默认配置
→ 使用机复制同一拓扑
→ 使用机真实主路径
→ 重建安装包
→ 安装包安装后主路径
```

不得跳过前一阶段，也不得用自动化测试、历史任务 done、组件能力卡或安装器能启动替代前一阶段。每一阶段的具体执行、证据、回退和停止动作必须按 `04-系统集成固定工作流与阶段门禁.md` 完成。

## 3. 开发机主路径

在全新隔离数据根中，只通过真实 Electron 可见 UI 完成：

1. 启动应用，默认数据根和默认配置可用。
2. 默认模型可用；未配置时错误明确且不伪装成功。
3. 创建学习计划、学期、课程、考试和任务。
4. 导入核心资料：PDF、DOCX、PPTX、XLSX、TXT、Markdown。
5. 导入图片并完成 OCR：PNG、JPG/JPEG、BMP、GIF、WEBP。
6. 确认资料进入业务存储，格式转换成功，`normalized_texts` 写入。
7. 生成结构化笔记并写入 `structured_notes`。
8. 生成知识模块并进入练习。
9. 完成练习、错题、重做和薄弱点更新。
10. 从真实课程/知识模块进入模拟考、速背或冲刺。
11. 生成、冻结和查看家长报告；投递状态和失败重试可见。
12. 使用 WAV 完成课堂转写；转写结果可编辑并可回到资料链。
13. 使用 Windows SAPI 朗读，并保存“已复习”状态。
14. 执行备份、恢复并检查业务数据完整性。
15. 关闭并重启应用，逐项确认上述关键数据仍可见。

旧 Office 扩展路径另行验收：

```text
DOC/PPT/XLS
→ WPS COM 转换
→ DOCX/PPTX/XLSX 文本提取
→ normalized_texts
→ 笔记/知识模块
→ 练习
→ 重启回读
```

## 4. 每条路径的证据

每个阶段必须记录：

| 字段 | 内容 |
|---|---|
| 用户动作 | 通过可见 UI 执行的动作 |
| 输入 | 文件类型、非敏感测试数据、当前上下文 |
| 预期结果 | 页面状态、数据库结果、后续可消费结果 |
| 实际结果 | 成功、失败或具体断点 |
| 证据等级 | 依据 `01-系统集成总览与客观认知.md` 的 E0-E7 |
| 运行根 | `H:\pi-studybuddy-tmp\runs\<task-id>\` 下的截图、DOM、日志或摘要 |
| 重启结果 | 是否关闭、重启后仍可见 |
| 问题引用 | 关联 `02-系统问题总账与整改清单.md` 的问题 ID |

DOM、日志和报告不得包含完整 UUID、绝对路径、真实密钥、学生资料原文或错误栈。

## 5. 运行资源交付

开发机闭环后，固化并记录：

- Electron 和内嵌 Node 版本；
- Python/OCR 运行资源版本和路径；
- whisper 可执行文件、DLL、模型和 SHA-256；
- WPS 版本、授权边界、ProgID 和 COM 健康结果；
- 默认配置和数据根规则；
- 启动健康检查和明确错误；
- 不随资源复制的凭据、生产数据库和学生数据。

使用机必须复制同一套已验证拓扑，不再另行设计第二套运行方式。WPS 无合法再分发许可时，使用机必须执行安装前置检查，不得偷偷打包 WPS 本体。

## 6. 安装包验收

安装包只有在开发机和使用机路径均通过后才能重建验收。安装包验收至少包括：

- 安装后启动；
- 空数据首次启动；
- 默认配置和默认模型；
- 核心资料到笔记、模块和练习；
- OCR/whisper 按已声明能力工作；
- WPS 前置或受控扩展检查；
- 报告、TTS、备份恢复和重启回读；
- 升级不丢数据；
- 卸载不误删用户数据；
- 资源缺失时明确失败而非静默降级。

## 7. 整体交付判据

只有同时满足以下条件，系统才能称为“正常运行并可交付”：

- 开发机从空数据完成主路径；
- 开发机重启回读通过；
- 核心格式不依赖 WPS 完成；
- OCR、whisper 和 WPS 的实际边界被验证并如实声明；
- 使用机复制同一拓扑后完成主路径；
- 安装包安装后完成主路径；
- 真实凭据和业务数据未泄露；
- 所有未完成问题仍在 `02-系统问题总账与整改清单.md` 登记；
- `04-Todo` 的历史 done 未被误解释为整体完成。

## 8. 停止规则

遇到以下任一情况，停止向下一阶段推进：

- UI 显示成功但数据库没有真实结果；
- Job 登记成功但后续业务不能消费；
- 依赖组件未找到或路径依赖用户 PATH；
- 重启后关键状态丢失；
- 使用 mock、fixture、handler 直调替代真实用户动作；
- 安装包缺少已声明的必要运行资源；
- WPS 许可、COM 或真实转换结果无法确认。

所有修复必须先回到当前开发机，修复后重新完成该阶段的真实路径和回读证据。
