## 4. 证据等级

| 等级 | 证据 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| E0 | 设计文档声明 | 应该具备的能力 | 代码或运行可用 |
| E1 | 源码、API、handler 存在 | 局部实现存在 | 生产接通、用户成功 |
| E2 | 单元/Adapter 测试 | 局部逻辑正确 | 系统集成、安装后可用 |
| E3 | 集成/Electron 自动化 | 受控链路可回归 | 空数据真实主路径、资源交付 |
| E4 | 开发机可见 UI 主路径 | 当前机器用户动作成功 | 重启持久化、使用机可用 |
| E5 | 开发机重启回读 | 当前机器数据生命周期成立 | 使用机和安装包可用 |
| E6 | 使用机真实主路径 | 复制拓扑可用 | 最终安装包发行质量 |
| E7 | 安装包安装后主路径 | 可支持最终发行判断 | 不代表所有未声明格式或外部组件均可用 |

系统集成中的“通过”必须标注达到的证据等级。

## 5. 系统集成主链

```text
空数据启动
→ 默认配置/默认模型
→ 创建学期、课程、考试、任务
→ 导入资料
→ 文件存储与格式转换
→ normalized_texts
→ structured_notes
→ knowledge_modules
→ S3 练习
→ S4 错题/重做
→ S5 冲刺
→ S6 报告
→ S7 课堂转写
→ TTS/已复习
→ 备份恢复
→ 重启逐项回读
→ 固化运行资源
→ 复制到使用机
→ 重建并验收安装包
```

任何一步失败，都回到当前开发机修复；不得以后一阶段的测试、安装或文档替代前一阶段的真实结果。

## 6. 能力边界

核心格式必须不依赖 WPS：PDF、DOCX、PPTX、XLSX、TXT、Markdown、PNG、JPG/JPEG、BMP、GIF、WEBP。

旧 Office 格式 DOC、PPT、XLS 作为受控扩展，经已安装且合法可用的 WPS COM 转换为新格式后进入同一文本管道。未完成 WPS 生产注入、真实转换和主链验证前，不得宣称旧 Office 闭环完成。

ODT、ODS、ODP、RTF、EPUB、TIFF 本轮不做，不阻塞核心交付。

## 7. 运行和用户原则

- 孩子不负责安装 Node.js、pnpm、Python、Git 或手工配置 OCR/whisper。
- 设置页只保留首次必要的 AI API Key、QQ SMTP 授权码/收件邮箱和飞书 Webhook。
- 默认模型、Windows SAPI、每周备份、数据目录和学习参数由系统提供默认值。
- 真实秘密、学生数据和生产凭据不得进入 Git、安装包、文档或日志。
- 外部组件缺失必须明确失败、可重试，不得把 Job 登记显示成成功。
