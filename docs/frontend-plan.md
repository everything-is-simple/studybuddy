# StudyBuddy 前端产品化实施计划（可编辑）

## 意图摘要

将当前集中在 `backend/app/main.py` 的单页测试工作区，渐进式改造成可日常使用的本地学习产品前端。首要问题不是一次性制作全部页面，而是优先建立可维护的应用壳，并完成一条可验证的核心闭环：**安全配置 AI Provider → 导入或选择材料 → 提问并查看引用 → 上传课堂音频 → 转写草稿 → 用户确认进入资料链路**。

本文件是前端改造的实施源文档，面向个人使用者、实现开发者和验收者。它只定义范围、契约、页面、验收和待确认事项；不代表任何 Provider、音频转写工具或页面已经真实可用。

> **已知边界**：`G:\WhisperCli` 目前尚未在本计划中被证实为可运行的命令行转写工具。其可执行入口、参数、输出格式、退出码、模型文件和隐私行为均须先审计。不能因为目录或 DLL 存在，就把它标为已接入或在 UI 中显示为可用。

## 1. 范围冻结

### 1.1 本轮目标（MVP 前端闭环）

本轮只交付支撑核心闭环所需的产品界面与后端契约，不将所有既有测试功能一次性搬迁：

1. **应用壳与导航**：稳定的页面框架、状态提示、窄屏导航和可访问的错误处理。
2. **总览**：让用户识别下一步、Provider 状态和待确认转写，而不是展示所有系统对象。
3. **资料库最小闭环**：导入/选择材料、查看处理状态、进入 Q&A。
4. **Q&A 最小闭环**：可编辑提问、请求状态、中文错误引导、可复核 citation。
5. **Provider 设置**：只通过后端受控 API 完成配置状态读取、写入和连接验证；密钥永不回显。
6. **课堂采集**：音频上传、任务状态、转写草稿、编辑、确认/拒绝/归档；只有经验证的转写 Provider 才能执行转写。
7. **WhisperCli 适配前置审计**：先确认本地依赖协议，再决定是否实施后端适配器。

### 1.2 明确不在本轮范围内

- 完整的学习计划、练习、错题、报告和交付中心页面；这些保留为后续阶段，不阻塞 MVP 闭环。
- 多用户、登录、云同步、远程共享数据根、多进程 worker、Electron 或移动原生应用。
- 在浏览器中写环境变量、保存 API key、执行本机命令或读取原始文件路径。
- 将未验证的真实 Provider、真实音频转写或真实外发标记为“已完成”或“real-pass”。
- 新建独立前端仓库、构建工具或框架迁移。除非原生 HTML/JS 拆分已经无法维护，否则保持 FastAPI 单进程、本地静态资源方案。
- 把现有单页测试 workspace 做成更大的单页；拆分后的页面应各自服务一个用户任务。

### 1.3 后续阶段（不纳入本轮验收）

- **F4 学习产品化**：今日计划、练习、错题、薄弱点和复习反馈。
- **F5 报告产品化**：本地报告生成、预览、导出、dry-run 与交付审计。
- **F6 体验收口**：跨页面一致性、性能基线、完整回归、操作文档和状态文档收口。

## 2. 不可破坏的系统约束

### 2.1 仓库与交付边界

- 正式实现、迁移和测试的唯一源目录是 `H:\studybuddy`。
- 生产后端代码位于 `backend/app/`，正式测试位于 `backend/tests/`，持久文档位于 `docs/`。
- `H:\studybuddy-composer` 仅用于组件实验，`H:\studybuddy-integration` 仅用于经验证组件的装配；不得把其中实现直接复制进正式系统而跳过契约验证。
- 不提交数据库、上传原件、生成物、测试输出、凭据、Provider key 或包含私有信息的绝对路径。
- 在新增页面资源前，先确认 FastAPI 的正式静态目录与挂载契约；不得临时在运行时创建业务目录或以 ad-hoc 路径提供资源。

### 2.2 安全与隐私边界

- API key 只在浏览器输入后通过受控后端请求写入批准的运行时/凭据存储；页面只显示脱敏配置状态。
- DOM、URL、浏览器日志、toast、错误体和诊断导出中不得包含 API key、数据根路径、原件绝对路径、完整 stderr、raw provider response 或不应公开的原文全文。
- 浏览器绝不直接启动 `G:\WhisperCli` 或其它本地可执行程序；本地 ASR 只能由后端适配器在受控超时、取消、审计和错误映射下执行。
- 任何外发/交付能力默认关闭；dry-run 必须清晰标示“未真实外发”。
- `deleted`、`unavailable`、`stale`、`pending_review` 与 `uncertain` 均为用户可见的一等状态，不得被渲染为正常可引用内容。

### 2.3 后端与数据约束

- 不以 UI 改造为由绕过现有 source lifecycle、revision、citation、operation/task、幂等或审计边界。
- 转写、索引和其它长任务必须复用正式 operation/task 契约；若现有 API 实际为同步操作，需先记录并评审契约缺口。
- 数据库模式变更必须通过 `backend/app/migrations/runner.py` 的连续、幂等、事务化迁移完成，并维持 `schema_migrations` 与 `PRAGMA user_version` 一致。
- 只允许使用安全、面向产品的 API 响应；禁止把 SQL、traceback、内部路径或 provider 原始错误暴露给浏览器。

## 3. MVP 信息架构与页面边界

### 3.1 一级导航（MVP）

- **总览**：下一步学习动作、待处理事项、最近材料、Provider 摘要、待确认转写。
- **资料库**：材料导入、选择、搜索/筛选、处理状态与材料详情入口。
- **问答**：围绕已选材料的线程、提问、回答与 citation 复核。
- **课堂采集**：新建采集会话、音频上传、转写任务、草稿编辑和确认接入。
- **设置**：Provider 配置与验证；系统诊断只读入口作为次级页面或对话框，不做设计者控制面板。

“学习”和“报告”在导航中是否显示为禁用预告、隐藏，或继续以已有入口保留，需在实施前确认；本轮不为它们制作伪完整产品页面。

### 3.2 屏幕文件原则

遵循 screen-file-first：每个独立用户任务使用独立 HTML 页面；多个页面存在时，`index.html` 只作为总览和入口，不承载整套产品 UI。

建议的**目标结构**（实际目录以既有 FastAPI 静态挂载契约为准）：

```text
backend/app/<confirmed-static-root>/
├── index.html                         # 总览
├── materials.html                     # 资料库
├── material-detail.html               # 材料详情
├── qa.html                            # Q&A 工作区
├── capture.html                       # 课堂采集与转写草稿
├── settings-provider.html             # Provider 状态、配置与验证
├── css/
│   ├── tokens.css                     # 从激活设计系统绑定的 token 合约
│   ├── app.css                        # 应用壳、组件、响应式规则
│   └── page-*.css                     # 仅在页面差异明确时使用
└── js/
    ├── api.js                         # 请求、错误码映射、取消与安全错误处理
    ├── shell.js                       # 导航、toast、dialog、mobile drawer
    ├── materials.js
    ├── qa.js
    ├── capture.js
    └── provider-settings.js
```

> **TODO（目录契约）**：确认现有静态资源目录、模板策略及 FastAPI mount 后，将 `<confirmed-static-root>` 替换为真实路径，并在本计划与实现说明中记录。不得新建无挂载、无测试的孤立 `frontend/` 目录。

### 3.3 页面间的最短任务路径

1. 用户在总览发现“Provider 未验证”或“待确认转写”。
2. 用户进入设置，完成安全配置与连接验证，返回原任务。
3. 用户在资料库导入或选择可用材料，等待/查看解析索引状态。
4. 用户进入 Q&A，提交问题，查看回答及 citation，并跳回材料。
5. 用户在课堂采集上传音频；只有 Provider 可用时才能开始转写。
6. 用户查看、编辑并确认转写草稿；确认后才将其接入资料/学习链路。

页面间应携带安全的资源标识和返回上下文；不通过 URL 写入 secret、原件路径或原文内容。

## 4. 页面需求与状态契约

### 4.1 总览 `index.html`

**用户任务**：快速判断现在应做什么。

**必须呈现**：

- 一个明确的主行动：继续学习、导入资料、配置 Provider 或处理转写草稿，按真实状态择一。
- 最近材料与其安全处理状态。
- Provider 摘要：未配置 / 已配置未验证 / 已验证 / 不可用；不展示密钥、端点中的敏感部分或原始异常。
- 待确认转写、来源不可用和失败任务的可操作入口。

**不应呈现**：系统对象大表格、所有诊断字段、设计设置面板或伪造的进度数据。

### 4.2 资料库 `materials.html` 与 `material-detail.html`

**用户任务**：安全地将资料引入后续问答和学习流程。

**MVP 功能**：

- 单文件导入；批量/文件夹导入须以当前 API 实际支持情况为准，不预设。
- 材料列表、搜索/筛选、解析/索引状态、失败重试入口。
- 材料详情：显示安全元数据、revision、来源状态及进入 Q&A 的范围入口。
- 删除、恢复和永久删除仅在既有 API 已支持时接入；删除前显示影响说明。

**状态矩阵**：空资料、加载中、导入中、解析/索引中、可用、失败可重试、已删除/不可用。

### 4.3 Q&A `qa.html`

**用户任务**：基于选定材料提问并复核回答出处。

**MVP 功能**：

- 可编辑问题输入框、发送按钮、提交中禁用与安全重试。
- 线程列表和当前线程消息时间线；若线程 API 未满足，先在契约清单中冻结缺口。
- citation 面板：材料标识、可用性、定位入口和 unavailable 说明。
- `provider_not_configured`、验证失败、超时、额度不足、空检索、来源失效等错误码对应的中文解释与下一步。

**响应式行为**：桌面有线程侧栏与 citation 侧栏；窄屏时线程改为抽屉，citation 改为可展开底部面板。输入框、发送、重试和 citation 定位均可键盘操作。

### 4.4 课堂采集 `capture.html`

**用户任务**：将课堂音频以可复核方式转成资料草稿。

**MVP 流程**：

1. 输入会话标题与可选课程/标签。
2. 选择并上传音频原件，获得安全的文件状态与资源标识。
3. 读取转写 Provider 能力状态；未配置/未验证时只给出设置入口。
4. 发起后端转写任务，显示排队、运行、失败、取消（若契约支持）和重试。
5. 展示分段草稿、时间戳（若 Provider 提供）、confidence/uncertain（若 Provider 提供）及可编辑正文。
6. 保存修订；用户明确确认后接入后续资料链路，或拒绝/归档。

**不可妥协项**：

- 绝不把上传成功表示为转写成功。
- 转写结果始终以 `draft` 开始；未确认内容不能静默替代用户材料。
- 如果 Provider 不输出 confidence 或分段时间戳，UI 必须如实显示“未提供”，而不是制造数值。
- 低置信度/uncertain 的标记必须可见、可定位、可编辑且不只依赖颜色。

### 4.5 Provider 设置 `settings-provider.html`

**用户任务**：无需直接编辑环境变量，也能完成受控配置和验证。

**页面分区**：

- Q&A Provider：状态、模型/超时等非 secret 参数、密钥输入、保存、验证结果。
- 转写 Provider：当前类型、状态、能力说明、验证结果；本地 WhisperCli 仅在适配器被证实并注册后出现为可选项。
- 脱敏诊断：安全的 request/correlation 标识、错误类别与建议动作；不导出 secret、路径或 raw response。

**必须遵守**：

- 输入密钥后清空输入框，不可回填、复制或从浏览器持久化读取。
- “保存”与“测试连接”是不同的可见动作，均需 loading、成功和失败状态。
- 真实连通测试的范围需由后端契约定义；不能在前端自行调用外部 Provider。
- 不在文档或实现中预设某个供应商、模型名或 base URL 已正确；配置选项由后端 capabilities/registry 驱动。

## 5. WhisperCli 与本地 ASR 的决策门

### 5.1 Gate W0：可执行协议审计（实施前阻塞项）

在编写任何真实 WhisperCli 适配器前，必须从 `G:\WhisperCli` 或其随附文档取得并记录以下事实：

- 实际入口：`.exe`、脚本、受支持的 DLL host 或其它受支持启动方式。
- 输入方式：文件路径、stdin、支持的编解码器、最大文件大小和语言参数。
- 输出方式：纯文本/JSON、段落、时间戳、confidence、语言信息及编码。
- 退出码、可分类的错误、超时/取消行为、子进程清理策略。
- 模型文件位置、首次运行准备、资源占用、并发限制和网络依赖。
- 是否会把音频或文本外发；若会，须更新产品隐私说明和用户确认流程。

**W0 通过证据**：可审阅的调用说明 + 最小 fixture 调用 + 脱敏输出样例 + 失败退出样例。仅看到 DLL、目录或人工口述均不构成通过。

### 5.2 Gate W1：正式后端适配器契约

W0 通过后，才可以定义并实现 `CaptureTranscriptionProvider`（名称以现有代码命名为准）的正式契约：

- 由后端创建受控子进程并传递受验证输入；浏览器只调用 API。
- 输入、输出、任务状态、错误分类、超时、取消、重试和幂等均纳入既有 operation/task 框架。
- 原始音频与完整工具输出不得写入常规日志；只保留必要且脱敏的审计字段。
- 输出映射到既有 transcript draft / segment 数据模型；不兼容字段显式记录为 `not_provided`。
- 先用 loopback/fixture 完成契约测试，再由用户 opt-in 使用一段非敏感音频做一次真实 smoke。

### 5.3 Gate W2：产品界面启用条件

- **未通过 W0**：设置页只能显示“本地 ASR 候选，尚未验证”；采集页禁用开始转写并提供说明。
- **通过 W0、未通过 W1**：可以展示诊断状态，但不得向用户开放真实转写动作。
- **通过 W1、未完成真实 smoke**：允许以“已接入，尚待真实环境确认”运行，测试证据必须区分 fixture/loopback 与 real-pass。
- **完成真实 smoke**：记录范围、日期、音频敏感性确认和限制；不得由一次 smoke 推导通用容量或可靠性承诺。

## 6. 视觉、响应式与交互基线

本项目使用当前激活的 **Apple 设计系统** 作为视觉方向，实施时须绑定其 token 合约，而不是沿用本文件旧版本中的 Neutral Modern 颜色和字体假设。

### 6.1 视觉原则

- 以 `--bg`、`--surface`、`--surface-warm` 的浅色层次和必要的深色章节组织信息；蓝色 `--accent` 只用于关键操作、链接、焦点和一个明确视觉焦点。
- 使用设计系统规定的 display/body/mono 字体栈、间距、圆角、边框与克制的层级；所有新颜色均从 token 合约取得。
- 页面保持产品真实感：不出现设计设置、viewport 选择器、目标数量标签、平台切换器或生成元数据。
- 资料、任务、状态和表单是主视觉；不使用装饰性 emoji、紫色渐变、暖米色底、虚构指标或无来源的性能承诺。

### 6.2 响应式合同

必须验证：`360`、`390`、`430`、`600`、`768`、`820`、`1024`、`1366`、`1440`、`1920px`。

- 采用流式 `clamp()` 尺寸、语义断点与必要的 container query；禁止通过缩小桌面卡片来伪造手机版本。
- 360–430px：侧栏转抽屉，表格转信息行，复杂筛选转可展开区域，触控操作保持可达。
- 600–834px：资料列表、任务状态和 citation 区域采用 1–2 栏过渡，避免信息密度突变。
- 1024px 以上：利用桌面空间展示任务上下文，但不让双侧栏挤压可编辑内容。
- 所有主要操作均有清晰 focus-visible、44px 以上的可触控目标（紧凑桌面控件应通过命中区保证可操作性）和可理解标签。

### 6.3 交互实现基线

- 输入、上传、发送、保存、验证、重试、取消和确认等动作必须是可实际触发、可观察状态变化的交互，而不是静态截图式页面。
- 使用统一请求层处理请求取消、错误映射、状态更新和 correlation/request 标识；不会把内部错误细节拼到页面。
- 使用语义化状态：加载与成功用 `role="status"`，失败用 `role="alert"`；不只依赖颜色或 toast。
- 重新加载后应保留浏览器级安全上下文（例如当前页面与非敏感资源选择）仅在现有安全策略允许时；绝不保留密钥或原文敏感内容。

## 9. 验收标准与证据

### 9.1 架构与可维护性

- [ ] 每个 MVP 一级用户任务都有独立页面边界；`index.html` 不成为巨型单页 workspace。
- [ ] 页面资源位于已确认的正式静态目录，路由/mount 有自动化测试或等价验证。
- [ ] 请求、错误映射和共享壳不在各页面复制；页面专属逻辑有明确文件边界。
- [ ] 不引入未经批准的前端框架、构建链或额外常驻进程。

**证据**：文件树、路由/静态挂载测试、页面级浏览器测试、代码审查记录。

### 9.2 MVP 用户路径

- [ ] 总览在首屏清晰显示一个真实下一步、材料摘要、Provider 摘要和待处理事项。
- [ ] 用户可导入/选择材料，看到真实解析或索引状态，并从详情进入 Q&A。
- [ ] 用户可以提交问题；请求期间阻止重复提交；回答附有可复核 citation 或明确的不可用说明。
- [ ] 未配置 Provider 时，资料库不受阻塞；Q&A/转写有可执行的设置引导。
- [ ] 已注册并验证的 Provider 仅在后端证据成立后显示为可用，并可完成最小 smoke。
- [ ] 音频流程清晰区分上传成功、任务运行、转写失败、草稿保存和用户确认；确认前不进入最终资料链路。

**证据**：端到端/浏览器测试、fixture 截图或状态断言、一次明确分级的 smoke 记录。

### 9.3 WhisperCli 与转写真实性

- [ ] 没有 W0 证据时，UI 不显示 WhisperCli “可用”或“已连接”。
- [ ] W0/W1/W2 的每一层状态都有对应证据，不把 fixture、loopback 和真实音频结果混为一谈。
- [ ] 后端适配器在超时/失败时清理受控进程，并且不把原始 stderr 或音频内容送到浏览器和普通日志。
- [ ] Provider 未提供的时间戳、分段或置信度不被 UI 虚构。

**证据**：适配器单元测试、任务集成测试、脱敏日志审计、用户授权的最小真实 smoke 记录（如执行）。

### 9.4 安全、隐私与数据生命周期

- [ ] DOM、请求/错误记录、下载文件和可见诊断中不包含 API key、绝对路径、traceback、SQL、raw provider response 或不应公开的原文。
- [ ] 浏览器不直接调用本地可执行程序、数据库或 Provider 外部 API。
- [ ] `deleted`/`unavailable`/`stale` citation 不显示为正常可引用内容。
- [ ] 用户的确认、拒绝、归档和重试调用具备既有幂等或等价的重复操作保护。

**证据**：安全 DOM 断言、API 错误测试、生命周期回归测试、手工审查清单。

### 9.5 响应式与可访问性

- [ ] 在 360、390、430、600、768、820、1024、1366、1440、1920px 无非预期横向滚动。
- [ ] 键盘可到达导航、主 CTA、上传、输入、发送、dialog、重试、citation 定位和草稿确认。
- [ ] 焦点可见；交互控件有名称；加载/成功/失败状态具备语义，不只依赖颜色。
- [ ] 手机布局在真实信息优先级上重排，线程与 citation 不挤压输入或阅读区域。

**证据**：指定宽度的浏览器测试、键盘测试、可访问性断言与人工复核。

## 10. 风险与缓解

| 风险 | 影响 | 缓解与停止条件 |
|---|---|---|
| 只发现 Whisper DLL，无法确认 CLI 协议 | 不能安全实现真实 ASR | 停在 W0；交付诚实的不可用状态，不编造 adapter |
| Provider 配置 API 不存在或不可安全写入 | 设置页无法形成闭环 | 先建立后端正式契约和测试；不让前端写环境变量/localStorage |
| 单页代码与已有浏览器测试紧耦合 | 拆页回归、功能丢失 | F0 建立映射与回归基线；按页面小步迁移 |
| 长任务状态不一致 | UI 显示假完成或无法恢复 | 复用 operation/task 契约；缺字段先补契约再做 UI |
| 产品范围重新膨胀 | MVP 长期不可验收 | F1–F3 完成前，不开启完整学习/报告页面开发 |
| 真实材料或音频进入测试证据 | 隐私风险 | 先 fixture/loopback；真实 smoke 仅经用户 opt-in，使用非敏感内容并保存脱敏证据 |
